# 逐层讲解

## 这个 skill 解决什么问题

技术概念往往不是「难」，而是**前置知识缺了一层**。用户看不懂解释，通常是因为解释里藏着他不知道的中间概念，而解释者一次性把它们全铺开了。

结果就是：用户看完一长段，感觉「好像懂了」，但实际没抓住任何一环，问不出具体问题，只能说「还是不太明白」。

逐层讲解的做法是：**每次只引入一个新概念，讲完停下来，让用户确认。** 用户确认了才继续，没确认就换个说法重讲这一层。

用户确认这个动作本身也是价值——它强迫用户暴露「哪一层没接上」，比他自己笼统地说「不懂」精确得多。

## 什么时候用

用户明确表示想被带着理解时。典型信号：

- 「教我 XX」「给我讲讲 XX」
- 「一点一点说」「由浅入深」「慢慢讲」
- 「我基础不好」「我忘得差不多了」
- 已经问过一轮但回复「还是不太明白」——这是最强烈的信号，说明上一轮讲法失效了

**不要**在用户只想要一个快速答案时用（比如「XX 命令怎么写」）。那种情况直接给答案。

## 核心规则

**讲完一层就停，等用户确认。**

不是三行、五行的限制——是**一次只推进一个认知台阶**。如果一层的内容里出现了两个新概念，那其实是两层，拆开。

停下来的时候，明确说「这里清楚吗」或「OK 吗」，让用户知道球在他那边。

## 怎么写每一层

**从用户已知的东西出发。**

第一层几乎总是从一个用户已经懂的事实或类比开始。比如讲 Istio 多网络，第一层是「两个 Pod 能通，是因为 IP 能路由到」——这是用户已有的认知，不需要解释。

**解释「为什么需要这个」，而不是「这个是什么」。**

概念的存在都是为了解决某个问题。先说问题，概念自然就落地了。比如不要直接讲「networkGateway 是跨网络网关开关」，而要先问「什么时候两个 Pod 不能直接通信」。

**用具体场景，不用抽象定义。**

抽象定义对初学者是负担。一个具体的例子（北京机房 / 上海机房）比一段准确的描述有用得多。

**一层讲完，可以给一个「到这里对不对」的小检查。**

比如「到这里清楚吗？清楚了我就说第二层（什么时候会不在一起）」。括号里预告下一层，让用户知道还有多少路要走。

## 用户确认之后

- **确认懂了** → 进入下一层，不要在上一层停留
- **说「还是不」** → 换一个角度重讲**同一层**，不要往前走。换个类比、换更简单的场景、或者退回更基础的一层
- **问了一个具体问题** → 先回答这个问题，它往往暴露了真正的卡点，然后回到主线
- **纠正你** → 用户可能是对的。先核实，不要坚持

## 用户纠正你的时候

这是最需要认真对待的情况。用户在这个领域可能有实践、而你只有文档。

**先去核实，不要辩解。** 查代码、查官方文档、查实际现象。核实后再回答：

- 你对 → 说清楚依据
- 用户对 → 明确承认「我说错了」，不要含糊过去
- 都不对 → 说清楚实际情况

**含糊地承认错误（「可能是我表达不清」）比直接认错更糟**——用户不知道到底谁是对的。

## 每一层都必须有凭据

**用户在学一个新东西，他没有能力判断你讲得对不对。** 这意味着你给出的任何错误信息，都会被他当成事实吸收进去，而且可能很久都不会发现。

凭印象回答在这个场景里是有害的，不是「不够严谨」而已。

所以，讲每一层之前，先问自己：**这一层的内容，我的依据是什么？**

**有依据的**（可以直接讲）：

- 刚读过的官方文档
- 刚看过的源码
- 刚在用户环境里跑出来的结果
- 用户刚刚告诉你的

**没依据的**（属于「我记得好像是」）：**先去查，不要讲。**

查的顺序：

1. **用户自己的环境** —— 代码、配置文件、集群实际状态。最权威，因为就是他要用的那个版本。
2. **官方文档** —— 但要确认版本对得上。文档经常滞后于代码。
3. **源码** —— 文档没写清楚时看源码。

**查不到怎么办？**

**明说「这个我不确定」，然后告诉用户去哪查。** 比如：

> 「这个参数我不确定具体行为，建议看 XXX 的官方文档 / 直接 `kubectl explain` 看一下。我不想凭印象给你一个可能是错的答案。」

**不要用「通常」「一般来说」「应该是」把不确定包装成结论。** 那等于把风险转嫁给一个没有能力判断的用户。

**也不要用模糊的话蒙混过去。** 宁可说「不知道」，也不要给一个听起来合理的猜测。

这一条适用于所有内容：参数含义、行为机制、默认值、版本差异、最佳实践。**尤其是「默认值是什么」和「什么情况下用」这类问题——最容易凭印象答错。**

## 不要做的事

- **不要一次讲好几层**，即使觉得「这几层很简单可以一起说」。用户觉得简单会自己说「这个我知道，往下」。
- **不要用「简单来说」「一句话总结」收尾然后继续展开**。那等于又多讲了一层。
- **不要在用户没确认时自己往下走**。宁可停在原地也不要越过用户的卡点。
- **不要堆砌术语**。术语是最后引入的，不是最先。
- **不要为了显得专业而加无关的背景**。用户要的是接上这一层，不是全面了解。

## 什么时候结束

用户说「懂了」「我明白了」「原来如此」并且不再追问时，可以问一句要不要往下深入，但不要强行继续。

用户主动说「继续」或问下一个问题时，自然进入下一层。
