# 写法

这一页要让人**读完就能用，并且知道哪里不确定**。

## 第一条：不写没验证过的句子

写完一段，逐句问：**这句我能指出依据吗？**

指不出依据的句子只有三种处理：去查、删掉、明确标注不确定。
**不允许写得像是确定的。**

### 「我在猜」的四个信号

看到这几类表述，停下来：

| 信号 | 例子 | 问题 |
|---|---|---|
| 模糊限定 | 一般来说、通常、大多数情况 | 说明没查具体行为 |
| 无依据比较 | 性能好很多、比 X 快 | 没说和谁比、快多少 |
| 想当然的因果 | 因为 A，所以 B | A 和 B 的关系没验证 |
| 精确得可疑 | 99% 的场景都不需要 | 这个 99% 从哪来的 |

### 改法

```
✗ 这个参数一般来说不太用
✓ 这个参数只在需要 X 时用；日常场景可以不设

✗ 性能会好很多
✓ 实测从 1.2s 降到 0.4s（本机，1000 次循环）

✗ --max-steps 默认是 100
✓ --max-steps 默认是 100（docker run --help，29.8.2 实测）
```

**第三种最好：把依据写在句子旁边。** 读者不信的时候能自己核。

## 一条事实的三种来源

| 类型 | 什么算 | 怎么标 |
|---|---|---|
| `run` | 你自己跑出来的输出 | 最可信，优先用 |
| `code` | 源码某一行 | 带文件名和行号 |
| `doc` | 官方文档某一页 | 带 URL |

**没有来源的句子不写。** 不确定就不写，不写不丢人；写错才丢人。

三种来源冲突时，以 `run` > `code` > `doc` 为准，并在正文里明说差异：

> 文档说默认 60 秒，但源码里 `DEFAULT_TIMEOUT = 20`（`config.py:28`）。以源码为准。

## 每页的结构

一页就是 `steps[]` 里的一项，字段固定：

```json
{
  "title": "这页的主题",
  "sources": ["key1"],
  "blocks": [
    { "type": "p", "text": "第一段是导语，必须是总起，不是废话。" },
    { "type": "p", "text": "之后是正文段落。" }
  ]
}
```

渲染顺序由模板决定，你只需要保证 **`blocks[0]` 是导语**。

**导语不要另写一段总结再开始正文**——那会重复。第一段就是正文本身。

页内分节用 `h3` 块：

```json
{ "type": "h3", "text": "分节小标题" }
```

**不要写 `## 标题` 这种 Markdown。** 块类型只有那十种，Markdown 语法会被当正文原样显示。

---

## 分节

一页最多 4 节。超过 4 节说明这页该拆。

分节标题用具体名词，不用抽象概括：

```
❌ 核心机制
✅ 一次调查怎么走完

❌ 配置说明
✅ 模型配在哪、谁覆盖谁
```

## 代码块

### 要能跑

```bash
brew install <tool>
<tool> --help
```

不要写"配置一下即可"这种。

### 标明是示意还是真实输出

真实输出：

```text
$ <tool> run "why is checkout 500?"
[tool] calling <api_name> ...
```

示意（结构演示，不是真跑出来的）：

```text
# 示意：一次调查的形状
你: 为什么 500
  ↓
Holmes: 先看 Pod → 拉日志 → 查 limit → 结论
```

### 命令要带上下文

```bash
# 只查某个告警，最多 3 个
<tool> investigate alertmanager \
  --url http://localhost:9093 \
  --alertname "KubePodCrashLooping" \
  -n 3
```

不要只贴一个参数，读者需要知道它在什么上下文里用。

## 表格

用表格的场景：**并列对比**。参数列表、选项对比、三种方式对比。

不要用表格的场景：**有先后顺序**（用有序列表）、**需要解释**（用段落）。

参数表第一列是键名，第二列一句话，第三列（可选）默认值。

**写成 `table` 块，不要写 Markdown 表格。** 引擎不解析 Markdown，`p.text` 里的
`| 选项 | 默认 |` 会原样显示成竖线。

```json
{ "type": "table",
  "head": ["选项", "默认", "说明"],
  "rows": [["--max-steps", "100", "工具调用轮数上限"]] }
```

**默认值必须写**。用户最想知道的就是"不给会怎样"。

---

## 旁注

两类：

- **要点**：容易被忽略但很重要的结论
- **小心**：会导致数据丢失、安全风险、浪费时间的行为

**写成 `note` / `warn` 块，不要写 Markdown 引用块：**

```json
{ "type": "note", "label": "要点", "text": "工具描述写得好不好，直接决定模型会不会用这个工具。" }
{ "type": "warn", "label": "小心", "text": "--bash-always-allow 会让模型能在你机器上执行任意命令。" }
```

一页最多两处。旁注多了就没有重点。

---

## 术语

首次出现给定义，一句话：

```json
{ "type": "p", "text": "一个 tool 就是一次可执行的动作，带名字和描述。tool 打包成 <strong>toolset</strong>，一个 toolset 管一个数据源。" }
```

不要写"顾名思义"、不要假设读者知道。

同一术语从头到尾用同一个词，不要一会儿 toolset 一会儿工具集。

---

## 配置入口必须点名

这是一个高频错误。写"可以用 X 改"而不说 X 是什么，新手完全没法操作。

```
❌ 目录可以用 HOLMES_CONFIGPATH_DIR 改。
✅ 目录本身由环境变量 HOLMES_CONFIGPATH_DIR 决定——注意它是环境变量，
   不是配置文件字段，也不是命令行选项。
```

判断规则：

| 长这样 | 是 |
|---|---|
| `--flag`、`-f` | 命令行参数 |
| `UPPER_SNAKE` | 环境变量 |
| `lower_snake` | 配置文件字段 |
| `ClassName.prop` | 代码里的属性 |

---

## 数字和量化

**数字必须能数出来。**

```
❌ 四种方式   （正文只有三条）
✅ 三种方式   （正文恰好三条）
```

**没有实测的量化不写。**

```
❌ 工具输出动辄上万 token
✅ 一次资源详情查询的输出可能超过上下文窗口，超出部分会被写到磁盘
```

---

## 删掉这些

| 写法 | 问题 |
|---|---|
| 值得注意的是 | 除了你自己没人觉得值得注意 |
| 换句话说 | 通常是重复上一句 |
| 总的来说 | 通常是重复整段 |
| 不只是 X，而是 Y | 装深刻，直接说 X 和 Y |
| 非常、极其、至关重要 | 程度词代替不了具体场景 |
| 赋能、闭环、抓手 | 黑话 |
| 首先/其次/最后 三段式 | 强行结构 |
| 每段结尾小结 | 一页写一次总结就够 |
| 建议根据情况调整 | 没替读者做决定 |
| 可以考虑优化一下 | 优化什么是空的 |
| 视情况而定 | 等于没说 |

**「建议」本身不是问题。** 给出具体值或做法的建议是文档里最值钱的部分：

```
✓ 建议把 --max-steps 设在 15–20，能防止死循环
✓ 建议用 --mount 而不是 -v，路径写错会直接报错
✓ 内存 512MB 以下建议加 -m 限制
✗ 建议根据实际情况调整参数
✗ 配置可以考虑优化一下
```

判断标准：**读者看完这句话，知道下一步做什么吗？**

---

## 关于加粗

一页最多两处。加粗多了等于没加粗。

选择标准：**如果这句被删掉，读者会不会做错事**。会，才加粗。

---

## 关于"正确但没用"的句子

这些句子都对，但删掉不影响理解：

- "X 是一个开源的 Y"
- "配置正确非常重要"
- "你可以根据自己的需求调整"

判断方法：**把这句话删掉，读者会不会少知道一件事**。不会，就删。

---

## 反例对照

同一件事，两种写法：

**差：**

> X 支持多种数据源，包括 A、B、C 等，你可以根据自己的需求进行配置。
> 配置完成后，X 会自动发现这些数据源。

问题：没有具体命令、没有说「自动发现」是怎么发现的、「多种」是多少种。

**好：**

> X 本身不认识这些后端系统，它认识的是 adapter。一个 adapter 管一个数据源，
> 启动时逐个做连通性检查，结果缓存在 `~/.x/status.json`。跑
> `x adapter list` 看你的环境里有几个是 enabled。

差别：给机制、给路径、给命令。

注意这两种写法的**形式**：以上是内容对照，实际写进 `content.json` 时，
以上三段各自是一个 `p` 块，引用格式不出现。
