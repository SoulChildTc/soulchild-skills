# Smart Home

按设备名控制智能家居设备。**每台设备能做什么，用 `<名> --list` 现查**，不需要任何设备手册。所有命令在项目根目录（`workdir`）执行。

## 核心原则

- **能力以 `<名> --list` 实时输出为准**，不凭经验猜能力名
- **设备名精确匹配**清单里的名字，不做包含/模糊猜测（防止误操作）
- **成败看退出码**（0 = 成功），细节用 `--json`
- 操作前先 `list` 确认设备名，`<名> --list` 确认能力，再执行

## Quick Reference

| 目的 | 命令 |
|---|---|
| 环境检查 | `node cli/device.mjs --status` |
| 配置平台 | `node cli/device.mjs --config`（打开浏览器登录） |
| 注册/刷新设备 | `node cli/device.mjs --register` |
| 设备清单 | `node cli/device.mjs list` |
| 设备能力 | `node cli/device.mjs <名> --list` |
| 动作/按键（无参） | `node cli/device.mjs <名> --action <动作>` |
| 动作/按键（带参） | `node cli/device.mjs <名> --action <动作> <参数>...` |
| 写属性 | `node cli/device.mjs <名> --set <属性> <值>` |
| 读属性 | `node cli/device.mjs <名> --get <属性>` |
| 设备改名 | `node cli/device.mjs --rename <旧名> <新名>` |

## 操作流程

1. **解析意图**：设备名 + 动作 + 参数
2. **确认设备名**：`list` 看清单，**精确匹配**；跨平台同名用 `平台:设备名`（如 `xiaomi:客厅灯`）
3. **查能力**：`<名> --list` 看该设备实际能力（可写/只读属性、动作/按键）——能力名 = 输出的名字
4. **选命令**：按能力类型操作——
   - 动作/按键（无参）→ `--action <动作>`
   - 动作/按键（带参）→ `--action <动作> <参数>...`（`--list` 会标注 `[带参]`）
   - 可写属性 → `--set <属性> <值>`
   - 读属性 → `--get <属性>`
5. 🔴 **CHECKPOINT（写操作）**：`--set`/`--action` 执行前，若存在任一以下情况，**先向用户确认目标与参数再执行**：
   - 设备名有歧义（多个候选）
   - 参数值不确定（用户没给具体值/范围）
   - 动作是破坏性或不可逆（如关机 turn-off、清空）
   - 读操作（`--get`/`--list`）无需确认
6. **执行**
7. **验证**：退出码 0 后，可读回属性用 `<名> --get <属性>` 读回确认实际生效
8. **汇报**（简短一句，如"音量已调到 22"）

## 意图 → 操作（通用）

> 能力名、枚举、范围以 `<名> --list` 实际输出为准。下表是常见意图的通用操作。

| 用户说 | 通用操作 |
|---|---|
| 调大/调小音量 | `--get volume` 看当前 → `--action volume_up/down` 或 `--set volume <±1>` |
| 音量调到 X / 静音 | `--set volume X` / `--set mute true\|false` |
| 开关机 | `--action turn-off` / `--action turn-on`（若无此动作，试 `--action power`） |
| 播放/暂停 | `--action play` / `--action pause` |
| 按主页/返回/方向 | `--action home\|back\|ok\|up\|down\|left\|right\|menu\|settings\|focus` |
| 切输入源/HDMI | `--set input-control N`（枚举以 `--list` 为准） |
| 查状态/音量/模式 | `--get <属性>`（枚举自动翻译） |

`--list` 输出的动作区，带参动作会标注 `[带参 --action <动作> <参数>]`（如 `post` 标注 `[带参 --action post <arg0>]`，调用时 `--action post "你好"`）。`--set` 只用于可写属性，不能代替 `--action` 传参。

## 退出码

| 码 | 含义 | 处理 |
|---|---|---|
| 0 | 成功 | 汇报结果 |
| 1 | 用法/参数错误 | 检查命令格式 |
| 2 | 设备未找到 | 名字没匹配到，问用户或 `list` |
| 3 | 不支持控制 / 无此能力 / 操作类型不符 | 如实告知，不要重试 |
| 4 | 设备拒绝 | 降级（如改按键）或如实告知 |
| 5 | 凭证缺失/失效 | 重新 `--config` |
| 6 | 设备离线 | 确认设备开机后重试 |
| 7 | 网络/超时 | 稍后重试 |
| 8 | 设备名歧义 | 用精确名（脚本已列出候选） |

**用法**：看退出码判断成败（0 = 成功），不要解析输出文本；需要细节用 `--json`。`--json` 里 `data.code` 非 0 但退出码 0 时，以实际报错为准，不伪装成功。

## Pitfalls

- **能力名不存在 / 操作类型不符（退出码 3）**：改用 `<名> --list` 查真实能力，不要重试
- **设备拒绝（退出码 4）**：降级策略——**写**被拒 → 改按键（如 `--set volume` → `--action volume_up`）；**读**被拒 → 如实告知，不降级；按键也被拒 → 如实告知
- **设备离线/关机**：云端拒绝（退出码 4/6）→ 如实告知用户需先开机，**不要在同一请求里反复重试**；用户确认开机后再试一次
- **不支持控制的设备**（如手环）：`list` 标记 ⚠️，如实告知，**不要反复 `--register` 重试**（重拉也拉不到定义）
- **凭证等同设备控制权**：绝不打印、绝不提交 git；凭证失效（退出码 5）→ 删状态目录 `auth.json` 重新 `--config`
- **按键被忽略**：操作后读回值未变 → 设备按键有节流，隔 2 秒重试一次再判定
- **设备特有限制**（如某设备 turn-on 无效）：以实际报错为准，被拒/无效就如实告知并降级

## 🛑 绝对不要（红灯）

| 动作 | 为什么 |
|---|---|
| 不要**猜设备名** / 用包含/模糊匹配 | 会误操作到别的设备；必须精确匹配清单名 |
| 不要**凭经验猜能力名** | 能力以 `<名> --list` 为准，猜错会报退出码 3 |
| 不要**解析输出文本判断成败** | 看退出码 + `--json` 的 `data.code` |
| 不要**伪装成功** | 设备拒绝/离线就如实告知 |
| 不要**反复重试**同一操作 | 退出码 3/6/7 重试无用，如实告知用户 |
| 不要**打印/提交凭证** | 凭证等同设备控制权，绝不入对话或 git |
| 不要**操作时跳过确认** | `--set`/`--action` 前按 🔴 CHECKPOINT 确认

## Verification

- 环境就绪：`--status` 显示凭证 ✅ 且设备能力 ✅
- 操作成功：退出码 0 + 可读回属性读回确认
