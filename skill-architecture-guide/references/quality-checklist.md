# 质量检查清单

这个清单覆盖 SKILL.md、引用文件、description 三个层面的检查。每次创建或审查 Skill 时逐项过一遍。

## SKILL.md 检查清单

- [ ] SKILL.md < 500 行
- [ ] 流程图标识（如果有）用 graphviz dot 格式，文字描述清晰
- [ ] 术语全文一致（不混用"API endpoint"和"URL"）
- [ ] 没有时效性信息（如果有，放在 <details> old patterns 段）
- [ ] 没有 Windows 风格路径（用 `/` 不用 `\`）
- [ ] 给 AI 推荐默认方案而不是列一堆选项
- [ ] 引用的文件真实存在且路径正确

## Frontmatter 检查清单

- [ ] `name` 仅小写字母、数字、连字符，1-64 字符
- [ ] `description` 第三人称，写触发条件不写工作流，1-1024 字符
- [ ] description 包含具体关键词和场景
- [ ] `allowed-tools` 列出了 skill 需要的工具
- [ ] `triggers` 覆盖用户可能说的各种表达
- [ ] 如果引用多级子文件，确认一级引用原则

## Reference 文件检查清单

- [ ] 每个文件 self-contained（AI 独立读取）
- [ ] 超过 100 行的文件有目录
- [ ] 没有 SKILL.md 已经定义过的重复内容
- [ ] 引用的脚本路径正确
- [ ] 文件名体现内容含义
- [ ] 不互相引用（都从 SKILL.md 出发）

## Description 检查清单

- [ ] 第一句概括做什么
- [ ] 补充了触发场景和关键词
- [ ] 第三人称
- [ ] 没有总结 workflow
- [ ] 不超过 1024 字符

## 常见反模式速查

| 反模式 | 问题 | 修正 |
|--------|------|------|
| 一个文件塞多个步骤/领域 | AI 加载了不需要的上下文，信噪比低 | 按步骤/领域拆成独立文件 |
| 引用文件没有目录 | Claude `head -100` 预览时看不到完整范围 | 超过 100 行加 Contents 目录 |
| Reference 文件互相引用 | Claude 可能部分读取子文件 | 所有引用从 SKILL.md 出发 |
| Description 总结了 workflow | AI 跳过 SKILL.md 正文 | Description 只写触发条件 |
| 过度解释基础概念 | 浪费 token、稀释关键指令 | 假设 AI 已有常识，只加它不知道的信息 |
| 文件名含义模糊 | AI 不确定什么时候该读 | 文件名体现内容（`wxmp-writing.md` ✅ `doc2.md` ❌） |
| 给太多并列选项 | AI 选错或犹豫 | 推荐一个默认方案 + 1-2 个备选路径 |
| 结论式流程 | AI 以为做完就结束了，实际上需要反馈循环 | 关键操作加验证步骤："改完了？跑检查，没过就回来修" |
